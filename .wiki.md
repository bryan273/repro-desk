# Project Summary
Repro Desk helps researchers assess whether a paper’s headline result can be reproduced. Its bilingual site explains an AI-assisted reproduction workflow, presents an illustrative sample report and summary figures for 32 papers and 6 models, offers three free pilot plans, and accepts paper-check requests.

An owner-only admin page manages incoming requests and displays anonymous visit and form-start statistics. The app now uses Repro Suite styling and shared sidebar navigation, while retaining its existing content and features.

# Project Module Description
- **Landing page:** English and Chinese content, workflow overview, sample report, honest-numbers section, pricing, FAQ, and request form.
- **Request submission:** Collects a paper link, claim, email, and pilot plan; validates and saves requests and returns a request number.
- **Anonymous analytics:** Counts visits and form starts at most once per browser session, without collecting personal details for analytics.
- **Admin:** Owner-restricted request management with funnel counters, status filtering, pagination, and editable request status.
- **Authentication:** Sign-in, callback, and logout flows protect admin access.
- **Shared app shell and navigation:** Sidebar navigation for landing-page sections and admin, plus links to other Repro Suite apps. Below 900px, navigation moves into a dismissible drawer.
- **Theme and language controls:** English/Chinese switching and light/dark themes; theme preference is saved under `repro.theme2`.
- **Backend API:** Request, site-event, auth, user, settings, storage, health, and AI Hub endpoints.
- **Blog:** Blog pages, article rendering, and prerendering utilities.

# Technology Stack
- **Frontend:** React, TypeScript, Vite, Tailwind CSS, and reusable UI components.
- **Backend:** Python, FastAPI, SQLAlchemy, and Alembic.
- **Authentication and integrations:** Atoms Cloud Web SDK and backend services.
- **Visual design:** Inter, Noto Sans SC, and JetBrains Mono; responsive light and dark themes.
- **Quality checks:** ESLint, Playwright configuration, and frontend plugin tests.

# Usage
- In `app/frontend`, install dependencies using the package manager matching the lockfile. Use `package.json` scripts for development, linting, and production builds.
- In `app/backend`, create a Python virtual environment and install dependencies from `requirements.txt`.
- Configure database, authentication, and platform environment settings before starting the backend.
- Apply database migrations with Alembic when setting up or updating the database.
- `app/start_app_v2.sh` is available as an application startup helper.
- Frontend linting and production build passed after the restyle. Visual verification covered desktop width in light mode; dark mode and 390px mobile width were not verified.
