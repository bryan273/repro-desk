# Project Summary
Repro Desk helps researchers assess whether a paper’s headline result can be reproduced. Its bilingual landing page explains an AI-assisted workflow—an agent reads the paper, writes and runs code, repeats the run from scratch and audits its work, then a human reviews the report. The site presents an explicitly illustrative sample report, shares summary figures for 32 papers and 6 models, offers three free pilot plans, and accepts paper-check requests.

An owner-only admin page supports request management and displays anonymous funnel statistics. Visit and form-start events are counted without collecting email or other personal details.

# Project Module Description
- **Landing page:** English and Chinese content, language preference, light/dark themes, workflow overview, sample report, honest-numbers section, pricing, FAQ, and request form.
- **Request submission:** Collects a paper link, claim, email, and selected pilot plan; validates and saves requests and returns a request number.
- **Anonymous analytics:** Records visits and form starts, at most once per browser session, and provides admin statistics for visits, form starts, submissions, and conversion.
- **Admin:** Owner-restricted page with funnel counters, request list, status filtering, pagination, and editable request status.
- **Authentication:** Sign-in, callback, and logout flows protect admin access.
- **Backend API:** Includes request, site-event, auth, user, settings, storage, health, and AI Hub endpoints.
- **Blog:** Blog pages, article rendering, and prerendering utilities.

# Technology Stack
- **Frontend:** React, TypeScript, Vite, Tailwind CSS, and reusable UI components.
- **Backend:** Python, FastAPI, SQLAlchemy, and Alembic.
- **Authentication and integrations:** Atoms Cloud Web SDK and backend services.
- **Quality checks:** ESLint, Playwright configuration, and frontend plugin tests.

# Usage
- Install frontend dependencies in `app/frontend` using the package manager matching the lockfile. Use the scripts in `package.json` to run development, lint, and production build tasks.
- Create a Python virtual environment in `app/backend` and install dependencies from `requirements.txt`.
- Configure database, authentication, and platform environment settings before starting the backend.
- Apply database migrations with Alembic when setting up or updating the database.
- `app/start_app_v2.sh` is available as an application startup helper.

Frontend linting, production build, Python syntax checks, and an English light-mode visual check passed for this change. Chinese content, dark mode, mobile layout, request submission, and admin login were not verified. New analytics counters begin at zero; existing requests may retain older plan codes.
